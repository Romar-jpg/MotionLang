# 🏃‍♂️ MotionLang Compiler (Lexer & Syntax Analyzer)

> **MotionLang** is a beginner-friendly, procedural programming language based on real-world motion and spatial actions. Replacing abstract jargon with tangible metaphors, it treats data as physical objects being gathered, transformed, stored, and routed through loops mimicking circular momentum.

This repository contains the **Lexical Analyzer (Scanner)** and **Syntactic Analyzer (Recursive Descent Parser)** for MotionLang, built in C from scratch without `<string.h>` dependencies for our Principles of Programming Languages (PPL) project (Group 3).

---

## 📊 Project Status

* ✅ **Phase 1: Lexical Analyzer (Completed)** — Reads `.mtnl` source files, tokenizes via manual DFA/switch-case state machines, and generates `Symbol Table.txt`.
* 🚧 **Phase 2: Syntactic Analyzer (In Progress)** — Core parser architecture, `Symbol Table.txt` reader, statement dispatcher, and panic-mode error recovery are complete. Statement and expression grammar rules are ready for module integration.

## 🚀 How to Clone, Build, and Run

### 1. Clone or Pull Latest Changes
Open your VS Code terminal and run:
```bash
git clone https://github.com/Romar-jpg/MotionLang.git
# Or if already cloned:
git pull origin main
```

### 2. Run Phase 1: Lexical Analyzer
Compile using the `Makefile` and pass a `.mtnl` file to generate `Symbol Table.txt`:
```bash
mingw32-make
```
* **Windows:** `.\motionlang_lexer.exe valid_test.mtnl`
* **Linux/Mac:** `./motionlang_lexer valid_test.mtnl`

To clean generated lexer build artifacts:
```bash
mingw32-make clean
```

### 3. Run Phase 2: Syntactic Analyzer
Once `Symbol Table.txt` is generated by the lexer, compile and run the parser:
```bash
gcc motionlang_parser.c motionlang_tokens.c parser_stubs.c parser_main.c -o motionlang_parser.exe (You may skip this)
.\motionlang_parser.exe "Symbol Table.txt"
```
*(Note: Replace `parser_stubs.c` with your team's statement/expression `.c` files as they are completed.)*


> **NOTE:** Every time may na-change sa code, you must **COMPILE** the project first before running the executable para mag-take effect yung changes.

## 🧩 Phase 2: Syntax Analyzer Integration Guide (What to Do Next)

The core parser engine is now pushed and ready. Team members assigned to statement and expression parsing should follow these steps to hook their modules into the shared parser architecture:

### 1. Shared Header & Core Files
* **`motionlang_parser.h`** — Shared blueprint (similar to `motionlang_tokens.h`) containing the `Parser` struct, stream navigation helpers, and all statement/expression function prototypes.
* **`motionlang_parser.c`** — Core engine that loads tokens from `Symbol Table.txt` (skipping table borders and wrapped comment lines), dispatches top-level statements (`parse_statement()`), and runs panic-mode error recovery (`syntax_error()` + `recover()`).
* **`parser_main.c`** — Entry point driver that loads `Symbol Table.txt` and invokes `parse_program(&parser)`.
* **`parser_stubs.c`** — Temporary placeholder functions that skip until `;` or `}` so the core engine compiles and runs standalone. **Remove or replace these stubs** as real statement/expression modules are added.

### 2. How to Implement Your Assigned Grammar Rules
1. **Pull the latest `main` branch** (`git pull origin main`).
2. Create your module file (e.g., `parser_statements.c` or `parser_expressions.c`) and include the shared header:
   ```c
   #include "motionlang_parser.h"
   ```
3. Implement the exact function prototypes declared in `motionlang_parser.h` based on our CFG:
   * **Statements:** `parse_declaration_stmt`, `parse_assign_stmt`, `parse_input_stmt`, `parse_output_stmt`, `parse_if_stmt`, `parse_loop_stmt`, `parse_flow_stmt`, `parse_routine_decl`
   * **Expressions:** `parse_expr`, `parse_or_expr`, `parse_and_expr`, `parse_rel_expr`, `parse_add_expr`, `parse_mul_expr`, `parse_unary`, `parse_exponent_expr`, `parse_primary`
4. Use the built-in stream helpers inside your functions:
   * `check(parser, TOKEN_...)` — Inspects the current token type without consuming it.
   * `match(parser, TOKEN_...)` — Consumes the token if it matches (useful for optional branches).
   * `consume(parser, TOKEN_..., "Error message")` — Requires the expected token; automatically triggers `syntax_error()` and sets `panic_mode` so `recover()` synchronizes at the next `;` or `}`.

### 3. Important Token Coordination Notes
* **Separate Quote Tokens:** String and character literals emit separate quote tokens in `Symbol Table.txt` (`DELIM_DOUBLE_QUOTE` $\rightarrow$ `STRING_LITERAL` $\rightarrow$ `DELIM_DOUBLE_QUOTE`, and `DELIM_SINGLE_QUOTE` $\rightarrow$ `CHAR_LITERAL` $\rightarrow$ `DELIM_SINGLE_QUOTE`). Remember to `consume()` the opening and closing quote tokens inside `parse_input_stmt` (`prompt(...)`) and `parse_primary`.
* **Increment/Decrement & Boolean Literals:** `++`, `--`, `true`, and `false` are not yet separate tokens in `motionlang_tokens.h` (`++` currently scans as two `OPERATOR_PLUS` tokens, and `true`/`false` scan as `IDENTIFIER`). Coordinate whether to add them to the lexer or match them in the assignment/primary parser rules.

## 🛠️ Phase 1: Lexical Analyzer Archive (Completed)

All four lexer modules are complete and integrated via `motionlang_tokens.h`:
* **Module 1 (Stream Handler):** Character-by-character reader (`stream.h`, `motionlang_stream.c`) tracking `current_line` and `current_column`.
* **Module 2 (State Transition & Token Matching):** Manual `switch-case` scanner (`motionlang_lexer.c`) handling identifiers, numbers, separated string/char quotes, `else if` merging, `#` single-line comments, `[# ... #]` multi-line comments, operators, and delimiters.
* **Module 3 (Token Structs & Keyword Registry):** Manual DFA keyword recognizer (`motionlang_tokens.c`, `motionlang_tokens.h`) built without `<string.h>`.
* **Module 4 (Test Suite & Build):** Extension validation (`.mtnl`), word-wrapped `Symbol Table.txt` formatting (`main.c`), and `Makefile` automation.

## ⚠️ Troubleshooting

| Error Type | Description & Solution |
| :--- | :--- |
| **Exit Code -1** <br>*(Undefined Reference)* | If you use the VS Code "Run" button and get this error, your editor is only compiling your active tab or missing module `.c` files. <br><br>**Solution:** Compile via terminal (`mingw32-make` for the lexer, or `gcc` listing all parser `.c` files) or update `.vscode/tasks.json` to compile `"${workspaceFolder}\\*.c"`. |
| **Error 4551** <br>*(App Control Block)* | Windows Defender or your antivirus may block freshly compiled `.exe` files. <br><br>**Solution:** Add your project folder to your Antivirus/Windows Security **Exclusions** list. |
